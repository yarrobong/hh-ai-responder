## Что показала реальная проверка

Первый существующий sync импортировал 20 вакансий, 0 откликов, 20 разговоров и
57 сообщений. Все разговоры получили candidate_action_required без HH raw status.

Исправлены конкретные причины:

- Переговоры извлекаются из `applicantNegotiations.topicList`. Произвольные JSON
  объекты страницы больше не принимаются за отклики, неизвестная страница — за
  успешный пустой результат.
- Пагинация переговоров и `nextFrom` чатов читаются полностью; повторение cursor
  останавливает sync с ошибкой.
- Sender определяется по `currentParticipantId` и типу участника HH. Неизвестный
  sender не считается работодателем по умолчанию.
- HH `DISCARD`, `INTERVIEW`, `RESPONSE` учитываются детерминированно, отдельно от
  последнего человеческого сообщения. Отказ и offer блокируют follow-up.
- Записи без текста сохраняются. Для 135 пустых записей с явным
  `workflowTransition` и `hasContent=false` добавлена отметка `hh_system_event=true`.
  Это идемпотентная нормализация: исходные sender/text/timestamp не переписаны.
  Служебные события исключены из очереди ответа, waiting_since, AI-контекста и
  метрик времени ответа.
- CLI `hh sync` без target больше не вызывает panic. Ошибки дают JSON report и
  ненулевой exit code. Повторный импорт сохраняет summary, match result, связи и
  локальный dismiss; повторные события employer_replied не создаются.
- Уточнения с пустым application_id не распространяются на чужие разговоры.
  Dashboard и audit используют общий ConversationStateResolver.

Один разговор может иметь несколько warning-кодов. 163 разговора не имеют
application в текущем локальном наборе: причина не угадывалась, искусственные
applications не создавались. У 98 applications отсутствует сохранённый match
result; полноценная оценка не выдумывалась из краткой карточки.

25 разговоров имеют конфликты ранее импортированной истории/типа сообщения:
исходные записи сохранены. У 2 разговоров HH возвращает `hasMore`; у 1 не
подтверждено наличие последнего сообщения в возвращённом наборе; у 1 недоступно
содержимое сообщения. Полнота всей исторической переписки этих разговоров
**не заявляется**. Они не допускаются к follow-up. Отсутствующий raw status также
требует ручной проверки. Автоматического устранения конфликтов и orphan-связей нет.
