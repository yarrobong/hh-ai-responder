# Before

ConversationStore:

The root `ConversationStore` owned the authoritative in-memory conversation
slice, JSON envelope, loading/saving, validation, local IDs, identity indexes,
message deduplication, immutable-history checks, activity refresh, state,
summary, claim, timeline, and process locking.

JSONConversationRepository:

The root `JSONConversationRepository` was a thin port-shaped delegator to
`ConversationStore`; it did not own persistence.

File:

`EmployerConversationsFilename` was `employer_conversations.json`, with a
version-1 envelope containing a non-null `conversations` array.

IDs:

Conversation and message IDs used the existing `kind-` plus 16 random-byte
hex format generated by `newKnowledgeID`.

Message identity:

Duplicate matching used local message ID or non-empty `(source, external_id)`;
content comparison used the domain `conversation.SameMessage` semantics.

Message history:

History was append-oriented. Existing messages had to remain an unchanged
prefix; duplicate imports were idempotent and conflicting replacements failed.

Summary:

Summary values were supplied by callers and persisted as part of the
conversation snapshot. Recorded candidate claims could not be erased by a
later upsert.

Claims:

Claims were conversation annotations, validated against an existing candidate
message and deduplicated by exact value. They were not promoted to Candidate
Knowledge.

Save semantics:

Mutations changed memory only. `Save` acquired the private process lock and
`saveUnlocked` supported the existing batched HH-read synchronization path.

Context/policy coupling:

The current root store is already limited to persistence plus compatibility
access. AI context, policy, HH synchronization, write safety, follow-up,
dashboard, and PostgreSQL behavior remain outside this extraction.

# New adapter

Implementation:

`internal/adapters/storage/json/conversation.go`

Port:

`ports.ConversationStore`

Dependencies:

The conversation implementation imports only `internal/conversation`,
`internal/ports`, `internal/platform`, and the standard library. It has no

conversation policy, HH, AI, Dashboard, configuration, or PostgreSQL.

# JSON contract

Path:

`employer_conversations.json` (or the caller-supplied path).

Schema:

Version `1`, envelope `{ "version": 1, "conversations": [...] }`, with the
existing normalized conversation, message, summary, claim, experience claim,
state, follow-up, relation, timestamp, activity, metadata, and raw-status
fields unchanged.

Missing:

A missing file loads as an empty store. Missing, empty, and malformed files are
not conflated.

Corrupt:

Unknown fields, trailing JSON, unknown versions, null collections, invalid
aggregates/messages/claims, and duplicate IDs/identities fail closed. Failed
loads preserve the prior in-memory snapshot.

Permissions:

The existing `platform.WritePrivateFileAtomic` behavior remains in use:
private directory mode `0700`, private file mode `0600` where supported, with
same-directory sync/close/rename and temporary-file cleanup.

# Conversation identity

Local ID:

Generated IDs retain `conversation-` plus 16 cryptographically random bytes
encoded as lowercase hex. Explicit IDs remain unchanged.

External identity:

`HHConversationID` is persisted and indexed as an opaque normalized string.
Non-empty duplicate external conversation identities remain rejected.

Duplicate semantics:

An upsert with an external identity and no local ID adopts the existing local
ID. Reassignment of an existing conversation, duplicate local IDs, and
duplicate external identities fail with the existing observable errors.

# Message contract

IDs:

Generated message IDs retain `message-` plus 16 cryptographically random bytes
encoded as lowercase hex.

External IDs:

Persisted unchanged; source-qualified external IDs are used for duplicate
lookup, while missing external IDs do not participate in that index.

Dedup:

Same local ID or same non-empty `(source, external_id)` plus equivalent domain
content returns the existing message. Changed content fails and never rewrites
history.

Append:

Conversation existence, message validation, ID generation, activity refresh,
ordering, and detached return values are preserved. Append does not save to
disk automatically.

Ordering:

Stored history retains insertion order. `Timeline` uses stable timestamp
ordering, so equal timestamps retain insertion order.

Immutability:

Upserts enforce the unchanged-message-prefix rule and preserve all previously
recorded claims. Later activity/state/summary operations do not rewrite message
bodies or metadata.

Service/system:

Normalized system/service messages, including empty text where the domain
allows it, survive persistence and restart. Policy decides whether they count
as meaningful human history.

# Persistence operations

Upsert:

Accepts a complete normalized snapshot, preserves immutable history and claim
ledger constraints, refreshes activity, updates in-memory state, and returns a
detached value.

AppendMessage:

Performs the existing identity/dedup and validation flow, then appends through
upsert without implicit disk write.

State:

`UpdateState` stores the supplied normalized status, next action, waiting time,
and follow-up value. It does not classify or apply terminal/reply policy.

Summary:

`UpdateSummary` stores caller-supplied normalized summary values without AI or
prompt generation.

Claims:

`AppendCandidateClaim` retains exact conversation claims and experience
annotations and preserves exact-value deduplication. Candidate state is not
consulted or mutated.

FollowUp:

`FollowUpState` round-trips unchanged; timing and suggestion policy remain
outside the adapter.

Save:

Explicit `Save` uses the private process lock. `SaveUnlocked` is available to
the existing outer batch lock choreography and performs no second process lock.

# Timeline

Ordering:

Stable chronological sort by message timestamp; ties retain append order.

Detachment:

Get/List/Timeline and compatibility snapshots deep-clone nested messages,
metadata, summaries, claims, experience claims, pointers, and maps.

Persistence only:

YES

# Root compatibility

Aliases:

`EmployerConversationsFilename`, `ErrConversationNotFound`, and the envelope
type remain root aliases to adapter-owned definitions.

Wrappers:

`JSONConversationRepository` remains a root port-shaped wrapper that delegates
directly to `jsonstorage.ConversationRepository` and synchronizes the legacy
mirror when needed.

Mirrors:

The root `ConversationStore.conversations` field is a transitional detached
mirror for existing root workflows/tests that inspect or construct fixtures
directly. Direct mirror changes are imported only through validated
`ReplaceSnapshot`; they cannot bypass adapter rules. Batch sync uses adapter
`Clone`, `SaveUnlocked`, and façade adoption rather than copying persistence
state or mutexes.
