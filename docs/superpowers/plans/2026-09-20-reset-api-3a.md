# RESET-API-3A Pre-live Controlled POST Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Harden the controlled HH API application path before any live use, add safe PilotArtifact export, and prove that validation performs zero real HH mutations.

**Architecture:** Keep the narrow `APIApplicationWriter` and existing `hhwritegateway.Service` boundaries. Decode bounded HH error bodies into typed provider evidence, disable redirects on the writer’s scoped HTTP client, restore the configured daily audit counter in the controlled command, and add a read-only `hh-api approval export` conversion from `PilotArtifact` to `APIApplicationApproval`. Preserve the existing targeted GET reconciliation and fail-closed application gates.

**Tech Stack:** Go standard library, existing `httptest.Server` fixtures, JSON artifacts, existing durable application-attempt and HH write-audit stores.

**Spec:** `docs/superpowers/specs/2026-09-20-reset-api-3-controlled-application-post-design.md`

## Global Constraints

- Never perform a real HH POST; all mutation tests use local `httptest.Server` fixtures.
- `HH_DRY_RUN=true` blocks every HH write, including applications, tests, chats, resumes, and status changes.
- Unknown critical provider state remains `REVIEW_REQUIRED`/blocked; no retry converts uncertainty into action.
- The controlled invocation cap is exactly one mutation; configured `HHMaxWritesPerDay=0` remains unlimited.
- Bounded provider bodies and sanitized structured evidence only; never log raw sensitive response bodies.
- Preserve existing CLI flags, cookies support, JSON compatibility, and browser/bulk write behavior.
- Use the exact selected vacancy and provider resume identity; never guess or invent a provider resume ID.

## Review Focus

- Structured `403` errors must classify `negotiations/already_applied` as `ALREADY_APPLIED` without requiring `409`, and OAuth values as `AUTH_REQUIRED`; add table-driven fixtures in `application_writer_test.go`.
- A `307` or `308` POST redirect must make exactly one request to the original endpoint and zero requests to the target; add redirect-count tests in `application_writer_test.go`.
- A configured daily limit must block when the durable counter is unavailable or at/above the limit, while zero remains unlimited; add gateway/runtime policy tests.
- Export must reject non-ready or non-MATCH pilot artifacts, preserve the exact letter/hash/nonce/freshness, normalize only the documented internal resume-ID prefix, and write atomically/private; add export tests.
- Dry-run of an exported approval must produce `WOULD_APPLY` and observe zero POSTs; add the realistic round-trip command test.
